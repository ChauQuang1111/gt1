Maximize the Number of Partitions After Operations
class Solution {
    public int maxPartitionsAfterOperations(String S, int k) {
        if(k == 26) return 1;
        char[] s = S.toCharArray();
        int n = s.length;
        int[] left1 = new int[n], left2 = new int[n];
        int[] partitions = new int[n];
        int mask1 = 0, mask2 = 0, count = 1;
        for(int i = 0; i < n; i++) {
            int filter = 1 << (s[i] - 'a');
            mask2 |= mask1 & filter;
            mask1 |= filter;
            if(Integer.bitCount(mask1) > k) {
                mask1 = filter;
                mask2 = 0;
                count++;
            }
            left1[i] = mask1;
            left2[i] = mask2;
            partitions[i] = count;
        }
        int ans = count;
        mask1 = mask2 = count = 0;
        for(int i = n - 1; i >= 0; i--) {
            int filter = 1 << (s[i] - 'a');
            mask2 |= mask1 & filter;
            mask1 |= filter;
            if(Integer.bitCount(mask1) > k) {
                mask1 = filter;
                mask2 = 0;
                count++;
            }
            if(Integer.bitCount(mask1) == k) {
                if((filter & mask2) != 0 && (filter & left2[i]) != 0 && Integer.bitCount(left1[i]) == k && (left1[i] | mask1) != (1 << 26) - 1) ans = Math.max(ans, count + partitions[i] + 2);
                else if(mask2 != 0) ans = Math.max(ans, count + partitions[i] + 1);
            }
        }
        return ans;
    }
}

* Bây giờ, nếu ta **đổi ký tự s[i]**, ta có thể chia nhóm này ra để tăng tổng số nhóm.

### 🟩 Điều kiện 1 (phức tạp nhất):


* `(filter & mask2) != 0`:
  → ký tự hiện tại **xuất hiện trùng** trong nhóm bên phải.

* `(filter & left2[i]) != 0`:
  → ký tự hiện tại **cũng trùng** trong nhóm bên trái.

* `Integer.bitCount(left1[i]) == k`:
  → nhóm bên trái tại vị trí `i` **cũng đã đầy k ký tự khác nhau**.

* `(left1[i] | mask1) != (1 << 26) - 1`:
  → hợp của 2 nhóm **không chứa đủ 26 ký tự** (vẫn còn chỗ để đổi thêm ký tự).

✅ Khi **tất cả các điều kiện này đúng** → việc đổi ký tự tại `s[i]` cho phép:

* nhóm trái và nhóm phải **đều thêm được 1 nhóm hợp lệ**
  → tổng số nhóm tăng thêm **2**.

👉 `ans = Math.max(ans, count + partitions[i] + 2);`

| **1. Trái → phải** | Ghi nhận số nhóm ban đầu và bitmask tại mỗi vị trí (`left1`, `left2`, `partitions`) |          |
| **2. Phải → trái** | Tính số nhóm bên phải và thử đổi 1 ký tự tại từng vị trí `i`                        |          |
| **3. Kết hợp**     | Kiểm tra điều kiện để xem đổi `s[i]` giúp tăng được 1 hoặc 2 nhóm                   |          |
| **4. Kết quả**     | Lấy giá trị `ans` lớn nhất                                                          |          |

---

## 📘 Ví dụ minh họa nhỏ

Giả sử:

```
S = "abca", k = 2
```

* Gốc: nhóm = ["ab", "ca"] → 2 nhóm
* Nếu đổi `c → b`: nhóm = ["abb", "a"] → 3 nhóm
  → `ans = 3`

---

Bạn có muốn mình **vẽ sơ đồ minh họa trực quan** từng bước khi `k=2`, để thấy **khi nào +1, khi nào +2 nhóm** không?
Cái này nhìn bằng hình rất dễ hiểu, đặc biệt phần `(filter & mask2)` hơi trừu tượng.
Rất hay 👍 — câu hỏi “**tại sao dùng `Math.max()`**” chính là trọng tâm của đoạn cuối này.
Giải thích chi tiết nhé 👇

---

### ⚙️ 1. Mục tiêu của bài toán

Thuật toán đang tìm **giá trị lớn nhất có thể đạt được** — ở đây là:

> ✅ **số đoạn con hợp lệ nhiều nhất** mà ta có thể chia chuỗi ra theo quy tắc `k`.

Vì ta duyệt qua **từng vị trí `i`** trong chuỗi và tính số phần tách được nếu cắt tại đó,
→ mỗi lần tính ra một **giá trị mới**, ta phải so sánh xem:

* giá trị mới này có **lớn hơn kết quả cũ (`ans`)** không?

---

### ⚖️ 2. Vì sao dùng `Math.max(ans, …)`

Câu lệnh:

```java
ans = Math.max(ans, count + partitions[i] + 1);
```

nghĩa là:

> Giữ lại giá trị lớn hơn giữa **kết quả hiện tại (`ans`)** và **giá trị mới tính được (`count + partitions[i] + 1`)**.

🧠 Vì trong quá trình duyệt:

* Có thể có nhiều cách chia chuỗi khác nhau,
* Ta chỉ cần **giữ lại cách tốt nhất (lớn nhất)**.

Nếu không dùng `Math.max`, mà gán thẳng `ans = count + partitions[i] + 1`,
→ kết quả cuối cùng có thể bị **ghi đè bởi giá trị nhỏ hơn** (sai).

---

### 📊 Ví dụ nhỏ

Giả sử có ba cách chia chuỗi:

| i | partitions[i] | count | Tổng |   |
| - | ------------- | ----- | ---- | - |
| 2 | 1             | 1     | 2    | ✅ |
| 3 | 2             | 1     | 3    | ✅ |
| 4 | 1             | 0     | 1    | ❌ |

Mỗi lần duyệt:

```java
ans = Math.max(ans, tổng);
```

* i=2 → ans = max(0,2) = 2
* i=3 → ans = max(2,3) = 3
* i=4 → ans = max(3,1) = 3

→ Kết quả cuối cùng đúng là **3**, tức là chia được tối đa 3 phần hợp lệ.

---

### 🧩 Kết luận

> ✅ Dùng `Math.max()` để **giữ lại giá trị lớn nhất** (tối ưu) khi có nhiều lựa chọn.
> Không dùng nó thì kết quả có thể bị ghi đè bởi giá trị nhỏ hơn và sai logic.

Rất hay 👏 — mình giải thích thật kỹ **công thức `count + partitions[i] + 1`** nhé.

## 🎯 Mục tiêu của bài

Ta cần chia chuỗi `s` thành **nhiều nhất số đoạn có thể**,
mỗi đoạn phải chứa **không quá `k` ký tự khác nhau**,
và ta **được phép đổi 1 ký tự bất kỳ** trong chuỗi để đạt tối đa số đoạn.

---

## 🧩 Công thức xuất hiện ở đoạn sau:

```java
else if (mask2 != 0)
    ans = Math.max(ans, count + partitions[i] + 1);
```

Ta đang xét **vị trí i** là “điểm chia” giữa phần trái và phải của chuỗi.

---

## 🧠 Giải thích từng phần

| Thành phần      | Ý nghĩa                                                  |
| --------------- | -------------------------------------------------------- |
| `partitions[i]` | Số đoạn hợp lệ ở **phía trái** (từ `s[0]` đến `s[i]`)    |
| `count`         | Số đoạn hợp lệ ở **phía phải** (từ `s[i]` đến hết chuỗi) |
| `+1`            | Do **đổi 1 ký tự**, ta có thể **tạo thêm 1 đoạn mới**    |

---

## 🔍 Tại sao chỉ cộng **+1** (mà không phải +2)?

Ta xét **tình huống chỉ một bên được lợi** khi đổi ký tự.
Cụ thể:

* `mask2 != 0` nghĩa là bên phải **có ít nhất một ký tự bị trùng**
  (tức là có thể “chia tách” một đoạn mới khi đổi ký tự).
* Nhưng **bên trái không đủ điều kiện** để chia thêm đoạn.
  → Nên chỉ bên phải được cộng thêm **1 đoạn**.

---

## 📖 Ví dụ minh họa

Giả sử:

```
s = "abcda"
k = 3
```

### 🔹 Bước 1:

Không đổi gì → chia được:

```
abc | da
```

→ 2 đoạn (partitions[i] + count = 2)

### 🔹 Bước 2:

Nếu **đổi ký tự thứ 3 `'c'` thành `'x'`**,
chuỗi trở thành `"abxda"`, chia được:

```
abx | da
```

Hoặc `"abc"` → `"abx"` giúp tách riêng thêm một đoạn mới.

→ Tổng cộng: **số đoạn tăng thêm 1**, nên ta có
`partitions[i] + count + 1`

---

## ✅ Tóm lại

Công thức:

```java
count + partitions[i] + 1
```

có nghĩa là:

> “Tổng số đoạn bên trái + bên phải, cộng thêm 1 đoạn mới được tạo ra nhờ phép đổi 1 ký tự.”

Điều kiện `mask2 != 0` đảm bảo rằng việc đổi ký tự **thực sự giúp tách thêm đoạn**,
chứ không vô ích.
