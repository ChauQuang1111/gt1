Avoid Flood in The City
class Solution {
    public int[] avoidFlood(int[] rains) {
        int n = rains.length;
        int[] fa = new int[n + 1];
        for (int i = 0; i <= n; i++) {
            fa[i] = i;
        }

     int[] ans = new int[n];  // Mảng kết quả: -1 nghĩa là ngày mưa, >0 nghĩa là hút khô hồ nào
Map<Integer, Integer> fullDay = new HashMap<>(); // Lưu hồ -> ngày nó bị đầy lần cuối

for (int i = 0; i < n; i++) {
    int lake = rains[i];
    
    if (lake == 0) { 
        ans[i] = 1; // Ngày khô: tạm gán 1 (sẽ đổi sau nếu cần)
        continue;
    }

    // Nếu hồ này đã bị đầy trước đó (chưa được hút)
    Integer j = fullDay.get(lake);
    if (j != null) {
        // Cần tìm 1 ngày khô giữa j và i để hút hồ này
        int dryDay = find(j + 1, fa);
        if (dryDay >= i) {
            return new int[]{}; // Không tìm được ngày khô hợp lệ -> ngập lụt
        }

        ans[dryDay] = lake; // Hút khô hồ này vào ngày dryDay
        fa[dryDay] = find(dryDay + 1, fa); // Loại bỏ dryDay khỏi danh sách ngày khô (Union-Find)
    }

    ans[i] = -1;  // Ngày mưa, không hút được
    fa[i] = i + 1; // Cập nhật UFDS: vị trí i đã xử lý
    fullDay.put(lake, i); // Lưu ngày mà hồ này bị đầy
}

return ans;

    }

    private int find(int x, int[] fa) {
        if (fa[x] != x) {
            fa[x] = find(fa[x], fa);
        }
        return fa[x];
    }
}

## 💡 Tóm tắt bài toán

Bạn có 1 mảng `rains`:

* `rains[i] > 0` → hôm đó **mưa ở hồ `lake = rains[i]`**, hồ đó **đầy nước**.
* `rains[i] == 0` → hôm đó **trời khô**, bạn có thể **chọn 1 hồ đầy nước để hút khô**.

Mục tiêu: sắp xếp cách hút nước sao cho **không có hồ nào bị ngập lụt** (nghĩa là mưa 2 lần vào cùng hồ mà giữa hai lần **không được hút khô**).

## 🧠 Mục đích của hàm `find()`

Hàm `find(x, fa)` có nhiệm vụ là:
👉 **Tìm “ngày khô” sớm nhất (nhỏ nhất) còn trống từ vị trí `x` trở đi.**

* `fa` là mảng **cha (parent array)** trong cấu trúc Union-Find.
* Ban đầu, mỗi phần tử là **cha của chính nó**: `fa[i] = i`.
* Khi 1 “ngày khô” đã được dùng (đã hút hồ nào đó), ta sẽ **nối (union)** nó với ngày kế tiếp (`fa[i] = i + 1`),
  để lần sau bỏ qua ngày này.

---

## 🧩 Code đầy đủ

```java
private int find(int x, int[] fa) {
    if (fa[x] != x) {
        fa[x] = find(fa[x], fa);
    }
    return fa[x];
}
```

---

## 🔍 Giải thích từng dòng

### 1️⃣ `if (fa[x] != x)`

* Kiểm tra xem `x` có còn là **ngày trống (cha của chính nó)** hay không.
* Nếu `fa[x] == x`, nghĩa là **ngày `x` vẫn còn trống**, ta có thể dùng nó.
* Nếu `fa[x] != x`, nghĩa là **ngày `x` đã được dùng rồi**,
  và nó đang **liên kết đến ngày trống tiếp theo** (`fa[x]` là cha của nó).

---

### 2️⃣ `fa[x] = find(fa[x], fa);`

* Đây là bước **đệ quy** (recursion) để **tìm tiếp ngày trống kế tiếp**.
* Đồng thời, gán lại `fa[x]` = kết quả tìm được → gọi là **đường nén (path compression)**.
  → Giúp lần sau tìm nhanh hơn (chỉ cần 1 bước nhảy).

---

### 3️⃣ `return fa[x];`

* Trả về **ngày trống sớm nhất còn dùng được**.

---

## 🧮 Ví dụ minh họa chi tiết

Giả sử có 7 ngày (`n = 7`):

```
fa = [0, 1, 2, 3, 4, 5, 6]
```

Tất cả ngày đều trống ban đầu (mỗi ngày là cha của chính nó).

---

### Bước 1: Dùng ngày 2 để hút hồ nào đó

```java
fa[2] = find(2 + 1, fa);  // fa[2] = find(3, fa)
```

➡ Tức là **ngày 2 đã dùng**, nên ta **nối** nó với ngày kế tiếp (3).
Kết quả:

```
fa = [0, 1, 3, 3, 4, 5, 6]
```

---

### Bước 2: Gọi `find(2, fa)`

Giờ ta thử tìm ngày trống sớm nhất sau ngày 2.

* `fa[2] = 3`, và `fa[3] = 3`
  → ngày 3 vẫn còn trống
  → `find(2)` trả về `3`.

---

### Bước 3: Giả sử tiếp tục dùng ngày 3

```java
fa[3] = find(4, fa);
```

➡ Giờ `fa[3] = 4`, tức là ngày 3 bị “bỏ qua”, nối với ngày 4.

Khi gọi `find(2)`:

* `fa[2] = 3` → `fa[3] = 4`
  → `find(2)` = 4 (ngày 4 là trống gần nhất).
  Và nhờ “path compression”, sau lời gọi này:

```
fa[2] = 4; // nén đường
```

## ⚙️ Tóm lại — cơ chế hoạt động

| Tình huống            | Kết quả         | Ý nghĩa                                       |
| --------------------- | --------------- | --------------------------------------------- |
| `fa[x] == x`          | trả về `x`      | ngày này còn trống                            |
| `fa[x] != x`          | đệ quy tìm tiếp | ngày này đã dùng, nhảy đến ngày trống kế tiếp |
| `fa[x] = find(fa[x])` | nén đường       | tối ưu cho lần tìm tiếp theo                  |

## 🚀 Tác dụng trong bài toán Avoid Flood

* Khi 1 hồ **bị mưa lần đầu**, ta lưu lại `fullDay[lake] = ngày`.
* Khi **mưa lại cùng hồ**, ta cần tìm 1 “ngày khô” nằm **sau ngày đó nhưng trước hôm nay**.

  ```java
  int dryDay = find(j + 1, fa);
  ```

  → `find()` giúp nhanh chóng tìm ra **ngày khô trống gần nhất** (O(α(n)) thời gian gần như O(1)).

> và tìm đến ngày khô còn trống sớm nhất — cực kỳ quan trọng để tránh tràn hồ kịp thời 💧

## 🔄 Path Compression (Nén đường)

Giờ nếu ta gọi `find(2, fa)` lần nữa:

1. `fa[2] = 3`
2. `fa[3] = 4`
3. `fa[4] = 4` → dừng lại, kết quả = 4
4. Nén đường: gán `fa[2] = 4`, `fa[3] = 4`

Kết quả sau nén:

```
fa = [0, 1, 4, 4, 4, 5, 6]
```

🌀 Giờ chỉ cần 1 bước là `find(2)` ra `4` ngay, không phải nhảy từng bước.


Sau nén đường:

```

```
