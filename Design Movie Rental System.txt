class MovieRentingSystem {
    private static class Node {
        final int shop;
        final int movie;
        final int price;
        Node(int shop, int movie, int price) {
            this.shop = shop;
            this.movie = movie;
            this.price = price;
        }
    }

    // Order: price ↑, shop ↑, movie ↑  (strict: never returns 0 for distinct nodes)
    private static final Comparator<Node> CMP =
        (a, b) -> {
            int c = Integer.compare(a.price, b.price);
            if (c != 0) return c;
            c = Integer.compare(a.shop, b.shop);
            if (c != 0) return c;
            return Integer.compare(a.movie, b.movie);
        };

    // Available copies grouped by movie
    private final Map<Integer, TreeSet<Node>> availableByMovie = new HashMap<>();
    // All currently rented copies
    private final TreeSet<Node> rentedSet = new TreeSet<>(CMP);
    // Quick lookup from (shop, movie) -> Node
    private final Map<Long, Node> byPair = new HashMap<>();

    private static long key(int shop, int movie) {
        return (((long) shop) << 32) ^ (movie & 0xffffffffL);
    }

### 📌 Các biến


* `availableByMovie`:

  * Map từ `movieId` ➝ `TreeSet<Node>`.
  * Với mỗi bộ phim (`movie`), lưu một `TreeSet` chứa tất cả bản copy của phim đó (từ các cửa hàng khác nhau).

  * Dùng để nhanh chóng tìm ra cửa hàng rẻ nhất đang cho thuê một bộ phim.

  * Cũng dùng `TreeSet` với cùng comparator, nên luôn có thể lấy ra những bản thuê rẻ nhất theo thứ tự mong muốn.


* `byPair`:

  * Map từ một **cặp (shop, movie)** ➝ `Node`.
  * Dùng để **truy xuất nhanh** đến đối tượng `Node` khi biết `shop` và `movie`.

    → Bởi vì key trong `HashMap` nên là 1 object duy nhất, việc “nén” cặp `(shop, movie)` thành một `long` là cách tiết kiệm bộ nhớ và tối ưu lookup.

### 📌 Hàm tạo key

```java
private static long key(int shop, int movie) {
    return (((long) shop) << 32) ^ (movie & 0xffffffffL);
}
```

👉 Ý nghĩa:

* Chuyển `(shop, movie)` thành một số `long` duy nhất.
* Cách làm:

  1. `((long) shop) << 32`: đẩy `shop` lên 32 bit cao của `long`.
  2. `(movie & 0xffffffffL)`: lấy 32 bit thấp của `movie`.
  3. Dùng phép XOR (`^`) để gộp chúng lại thành một số `long`.

💡 Nhờ vậy, ta có một key duy nhất cho từng `(shop, movie)` và dùng được trong `HashMap<Long, Node> byPair`.

 Đoạn code này định nghĩa một **Comparator** trong Java để so sánh các đối tượng `Node`. Đây là cách để sắp xếp các `Node` theo nhiều tiêu chí (multi-level sorting).

👉 Giải thích từng dòng:

```java
private static final Comparator<Node> CMP =
        (a, b) -> {
            // So sánh theo giá (price)
            int c = Integer.compare(a.price, b.price);
            if (c != 0) return c;  // Nếu giá khác nhau thì trả về kết quả so sánh

            // Nếu giá bằng nhau thì so sánh theo shop
            c = Integer.compare(a.shop, b.shop);
            if (c != 0) return c;  // Nếu shop khác nhau thì trả về kết quả so sánh

            // Nếu cả giá và shop đều bằng nhau thì so sánh theo movie
            return Integer.compare(a.movie, b.movie);
        };
```

---

### 🚀 Thuật toán so sánh (Comparator logic)

1. **So sánh theo `price` (giá)**:

   * Nếu `a.price < b.price` → trả về số âm (nghĩa là `a` đứng trước `b`).
   * Nếu `a.price > b.price` → trả về số dương (`a` đứng sau `b`).
   * Nếu bằng nhau (`a.price == b.price`) → tiếp tục bước 2.

2. **So sánh theo `shop`** (nếu giá bằng nhau):

   * Giống logic ở trên, nhưng dựa vào `shop`.

3. **So sánh theo `movie`** (nếu giá và shop đều bằng nhau):

   * Đây là tiêu chí cuối cùng để phân biệt hai `Node`.

---

### 📝 Ý nghĩa:

* Comparator này đảm bảo rằng danh sách `Node` luôn được **sắp xếp theo thứ tự**:

  1. `price` tăng dần,
  2. nếu trùng giá thì `shop` tăng dần,
  3. nếu cả shop và giá trùng thì `movie` tăng dần.

💡 Đây là dạng **lexicographic order** (giống như từ điển: so sánh chữ cái đầu, nếu bằng thì sang chữ tiếp theo).
